# MITRA Repository Current State

## 1. What is implemented
The core data processing and analytics pipeline is fully implemented via `run_pipeline.py`. It executes sequentially through the following phases:
- Data Loading and Quality Reporting
- Data Cleaning (removing duplicates, cancellations, negative quantities, filling missing values)
- Core Business Metrics Computation (Revenue, AOV, Order counts, etc.)
- Product Intelligence
- Market Basket Analysis (Apriori association rules)
- RFM Customer Segmentation
- Seasonality Analysis
- Synthetic Economics (COGS estimation)
- Inventory Modeling (Demo stockout risk)
- Demand Forecasting (Time-series evaluation)
- Business Brain (Assembling all insights into a `merchant_business_profile.json`)

## 2. What works
- The end-to-end pipeline script (`run_pipeline.py`) runs successfully and outputs all expected data artifacts.
- Data cleaning logic robustly handles dirty data.
- The `mlxtend`-based Market Basket Analysis correctly generates association rules.
- The `statsmodels` and `scikit-learn` forecasting module successfully evaluates multiple models (Moving Average, Exponential Smoothing, Ridge Regression, Gradient Boosting).
- The test suite (`tests/test_pipeline.py`) successfully tests all major analytical functions using synthetic fixtures.

## 3. What is partially implemented
- `src/recommendations/`: The directory exists, but it is not integrated into `run_pipeline.py`.
- `src/simulation/`: The directory exists, but is currently unused in the main pipeline.
- Inventory and Economics modules use purely synthetic/demo logic and hardcoded ratios, acting as placeholders for real data.

## 4. What is missing
- **API Layer**: `src/api/` contains only an `__init__.py`. There is no web server or REST API (e.g., FastAPI) to serve the generated data to frontends.
- **Real Integrations**: Real merchant COGS and actual inventory stock levels are not yet integrated.
- **Recommendation Engine Integration**: The recommendations logic is not yet applied to end-user facing outputs or exposed via API.

## 5. Existing data flow
1. **Raw Data**: `data/online_retail_II.csv` -> loaded and validated -> `data_quality_report.json`.
2. **Clean Data**: Cleaned and saved as `data/clean_transactions.csv` and `.parquet`.
3. **Analytics**: The clean dataset is fed into various analytics modules (Metrics, Basket, RFM, Seasonality, ML Forecasting).
4. **Derived Data**: Generates intermediate CSVs (e.g., `customer_segments.csv`, `product_economics.csv`, `inventory_model.csv`).
5. **Final Aggregation**: The Business Brain module aggregates all insights into `data/merchant_business_profile.json`.

## 6. Existing module dependencies
- **Data processing**: `pandas`, `numpy`
- **Machine Learning / Stats**: `scikit-learn`, `statsmodels`, `mlxtend` (for Apriori)
- **Testing**: `pytest`
- **Configuration**: Uses Python's standard `os`, `json`, `logging`, and `pathlib`.

## 7. Existing outputs
All outputs are saved in the `data/` directory:
- `clean_transactions.csv` / `.parquet`
- `data_quality_report.json`
- `product_performance.csv`
- `product_relationships.csv`
- `customer_segments.csv`
- `seasonality_features.csv`
- `product_economics.csv`
- `inventory_model.csv`
- `merchant_business_profile.json` (The final master profile)

## 8. Existing tests
- `tests/test_pipeline.py` provides comprehensive unit tests using `pytest`.
- Tests cover the cleaner, metrics, product performance, RFM segmentation, basket analysis, synthetic economics, and inventory models using a small synthetic DataFrame fixture.

## 9. Any bugs or architectural problems
- **Monolithic Pipeline**: `run_pipeline.py` is a monolithic, sequential script. It may struggle with scalability or resume-ability if a single phase fails. It might eventually need an orchestrator (like Airflow, Prefect, or Dagster).
- **Performance bottlenecks**: Apriori algorithm for Market Basket Analysis can be highly memory-intensive and slow for large datasets (currently bypassed with `--skip-basket` when needed).
- **Silent Fallbacks**: The forecasting module catches exceptions and falls back to a simple Moving Average. This could mask underlying data issues in production.
- **Synthetic Logic**: The inventory and economics modules are labeled as synthetic/demo. They cannot be used for actual financial reporting without real underlying data.

## 10. The exact recommended next implementation step
**Implement the API Layer (`src/api/`)**:
Create a FastAPI application in `src/api/main.py` to expose the insights generated by the pipeline. The API should serve the `merchant_business_profile.json`, product relationships, and RFM segments via REST endpoints so that a frontend application or dashboard can consume the analytics.
